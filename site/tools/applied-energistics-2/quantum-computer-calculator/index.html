      What the code actually says

      Glass outside, one core inside

      Every block on the outside, edges and corners included, must be Structural Glass, and glass can't go inside. The inside must be full: exactly one core, at most one Data Entangler and one Multi-Threader (the config allows two), and any mix of the rest. So the smallest Quantum Computer is 3×3×3, and fitting all three special blocks takes 3×3×5. In-game, a second core, entangler or multi-threader, glass or air inside, a unit or core on the shell, and an AE2 crafting unit inside each stopped it forming.

      shell:  quantum_structure only
inside: 1 core
        ≤ maxDataEntanglers, ≤ maxMultiThreaders
        units, 128M, 256M, accelerators
no air, no AE2 crafting blocks
      AdvCraftingCPUCalculator.verifyInternalStructure

      Max size is blocks a side

      The size check lets the far corner sit maxSize − 1 past the near one, so the default 7 means up to 7×7×7, and each side can differ. That's 125 blocks inside at most. AE2's own CPU goes to 17 a side. In-game on ATM10's config, a 7×7×7 forms and an 8×7×7 doesn't.

      max − min ≤ quantumComputerMaxSize − 1
inside = (X − 2) × (Y − 2) × (Z − 2)
      AdvCraftingCPUCalculator.checkMultiblockScale

      Multipliers add, they don't stack

      The core and every accelerator give the same threads. A Multi-Threader multiplies the total, a Data Entangler multiplies the storage. With two of either, their multipliers are added: two ×6 entanglers make ×12, not ×36. ATM10, ATM10: Aeronautics and All the Mons raise the threads to 12 and both multipliers to 6.

      bytes   = Σ storage × (E·entangler× or 1)
threads = (1 + accelerators) × threads
          × (T·multiThreader× or 1)
      AdvCraftingCPUCluster.addBlockEntity

      Every job gets every thread

      An AE2 CPU runs one job at a time. A Quantum Computer runs as many as its bytes hold: each job reserves only its own bytes, and each one gets the full thread count and its own push budget. Two jobs push twice as fast as one. In-game, a lone core on ATM10's config sent 3.24 patterns a tick (65 a second, 12 threads), and two jobs on it at once sent 3.26 a tick each.

      job fits if bytes ≤ free storage
per job: ops = threads + 1 − (sent in last 3 ticks)
         max/s = 5 × (threads + 1)
      AdvCraftingCPUCluster.submitJob · AdvCraftingCPULogic.tickCraftingLogic

      It's picked before any AE2 CPU

      When a job is placed automatically, any Quantum Computer with room for it wins over every AE2 CPU, whatever their speed. Among Quantum Computers, the one with the most threads goes first. In-game, both jobs went to a 12-thread lone core while a 24-co-processor AE2 CPU on the same network sat idle.

      QC with free bytes ≥ job? → QC
else → AE2's own choice
      MixinCraftingService.onSubmitJob

      A lone core is a whole computer

      A single Quantum Computer Core with no other Quantum Computer block beside it forms on its own: 256M of storage and one block's threads, for 1 AE/t. A formed core only takes cables from above or below.

      if (min.equals(max)) return true;
core sides: UP, DOWN
      AdvCraftingCPUCalculator · AdvCraftingBlockEntity.getGridConnectableSides

      Touching computers don't merge

      Like AE2, it checks the layer just outside the box. Any Quantum Computer block against a face stops it forming. Two that line up don't merge as AE2 CPUs do, because the merged box would have glass and two cores inside. An AE2 CPU may touch it: they don't count each other. We checked all three cases in-game.

      for each side of the box:
  any Quantum Computer block in the next layer out?
    → don't form
      MBCalculator.verifyUnownedRegion

      One channel, 1 AE/t a block

      The whole Quantum Computer is one multiblock node, so it takes one channel however big it is. Every block draws the default 1 AE/t, glass included, so a 7×7×7 draws 343 AE/t. Each pattern sent costs 1 AE per input item.

      channels   = 1
idle power = blocks × 1 AE/t   (2 FE/t)
